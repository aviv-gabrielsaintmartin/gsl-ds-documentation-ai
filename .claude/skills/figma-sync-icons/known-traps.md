# Known Traps & Resolutions — figma-sync-icons

| Trap / Behavior | Root Cause & Resolution |
|---|---|
| **The "Icons" page has a `Placeholders` category that isn't real icon content** | Confirmed live 2026-08-27: the frame holds 2 generic `COMPONENT_SET`s named `placeholder` and `Figma component` — template/default content, not product icons. Never register this frame. |
| **Icon variant properties are not uniform across the library** | Most icons are a simple `{Name, Filled}` (On/Off) pair, but real outliers exist: `Circle`/`Square`/`Half`/`Triangle` shape-variant props (e.g. `star`, `exclamation`), a `Platform` prop (e.g. `share`), and single-variant icons with only a `Name` prop (e.g. `resize`, `loader`, `crop-simple`, `key-skeleton`). Store the full `componentPropertyDefinitions` object per icon rather than assuming a fixed `{Name, Filled}` shape. |
| **A `filled` (lowercase) prop is a typo, not a different convention** | `face-grin-hearts-light` and `face-sunglasses-light` (Users & People) use a lowercase `filled` key instead of the standard `Filled`. Preserve the typo verbatim in the registry — same convention as `figma-sync-component-sets`'s typo-preservation trap — don't silently normalize casing. |
| **A duplicate top-level layer name can hide a mislabeled component — check the internal `Name` variant, not just the layer name** | `water-ladder` appears twice in the `Lifestyle` category (different keys/node IDs). One is genuine (its internal `Name` variant also reads `water-ladder`). The other's layer is named `water-ladder` but its internal `Name` variant property reads `film` — and no `film` icon exists anywhere else in the registry, so this looks like a duplicated/renamed `film` icon whose layer name was never corrected, not an intentional second `water-ladder`. Always cross-check `componentPropertyDefinitions.Name.defaultValue` against the layer name when two icons collide — don't assume a name match at the top level means the component is really what it says it is. Flagged 2026-08-27 for design-owner confirmation before renaming or removing; both entries kept with a `note` field pending resolution. |
| **The same icon name can legitimately repeat across different categories** | `apple` exists in both `Brands` (the Apple logo) and `Nature & Food` (the fruit) — same name, unrelated icons, different keys. Because the registry keys icons within their category (not globally), this needs no special handling — just don't assume a bare name lookup across the whole registry is unambiguous; always resolve within a category first. |
| **An icon name can carry a trailing space, and nothing renders it** | Found 2026-09-14: `assistance `, `virtual-staging ` and `two-three-dimensional-draw ` each ended in a space. A trailing space is invisible in Figma's layer list, in the registry JSON, and in any markdown generated from it, so an agent matching `assistance` finds nothing while appearing to have searched correctly. **Check `name !== name.trim()` on every extraction** and report it — do not silently trim, because the registry must record what Figma actually holds until the library is fixed. Gabriel renamed all three the same day; the sync that followed showed the same `key` and `nodeId` on both sides, which is how a rename is told apart from a deletion. |
| **This SKILL.md names the Desktop Bridge, which is retired** | The Prerequisites table says to run `Plugins → Development → Figma Desktop Bridge`, and the steps call `figma_get_status` and `figma_execute`. Neither tool existed in the 2026-09-14 session, and Gabriel's own note records `figma-console-mcp` ("Desktop Bridge") as unmaintained and not to be used. **The working path is `figma-cli` at `~/figma-cli`**, which is not on PATH: run `cd ~/figma-cli && node src/index.js <cmd>`. `run <file>` and `eval <code>` give the same plugin context Step 2 needs — `figma.loadAllPagesAsync()`, page lookup, `componentPropertyDefinitions` all work unchanged. **The plugin stops when Figma switches files**, so a sync that worked minutes ago can fail with `fetch failed` for no reason other than the owner opening a different document; only Gabriel can restart it from `Plugins → Development → FigCli`. |
